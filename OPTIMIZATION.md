# Исправления производительности — 15 октября 2026

Для игры на одном компьютере откройте PLAY.html после распаковки архива. Интернет и установка сервера не нужны. Онлайн-сервер запускается по инструкции в README.md.

## Что изменено

- Удалено синхронное считывание и сканирование пикселей кузова во время отрисовки. Границы изображения рассчитываются из геометрии рисунка и водителя; выбранные машины подготавливаются в гараже.
- Геометрия колёс, ведущие оси и момент инерции переиспользуются. Правки редактора, включая перетаскивание, обновляют кэш; подвеска больше не сравнивает JSON в каждом кадре.
- Панорамы используют исходные декодированные изображения вместо дополнительных больших холстов. Убран сброс и очистка неиспользуемого полноэкранного фонового холста.
- Небо и облака вынесены в слои браузера; динамические дальние планы и игровые объекты сохраняют порядок отрисовки.
- Статические участки дороги кэшируются в координатах мира. Мосты и их деформация продолжают рассчитываться и рисоваться в реальном времени. При новой трассе кэш сбрасывается по seed.
- Кэши дороги и кузовов ограничены 24 и 12 миллионами пикселей соответственно. Коэффициенты генерации рельефа рассчитываются один раз для seed.
- Качество учитывает фактические интервалы между кадрами и частоту экрана. Медленный браузер может уменьшить внутреннее разрешение; настройки физики и размер мира сохраняются.
- Счётчик показывает фактический FPS и 95-й процентиль времени кадра. Расчётная пропускная способность JavaScript больше не выдаётся за FPS.
- Отмена анимации перехода при смене размеров окна или ориентации больше не вызывает необработанную ошибку.

## Проверка

Использован доступный ноутбук с Ryzen 7 H 255 / Radeon 780M. Проверки не подтверждают производительность на отдельном стационарном компьютере пользователя.

При окне 1440×900 и фиксированном внутреннем разрешении 2880×1800 в Edge максимальная стоимость отрисовки в первых 30 кадрах на пяти трассах снизилась с 69–166 мс до 7–18 мс. Это короткие последовательные заезды с одинаковым seed; другие фоновые процессы, сцены и устройства могут менять результат. Средний FPS не отражает отдельные задержки.

В Firefox 157.0.1 отдельный семисекундный заезд на холмах с фиксированным внутренним разрешением 2880×1800 дал около 120 FPS после исправлений. Проверка с возвращённым прежним механизмом фоновых слоёв дала около 79 FPS. Автоподстройка разрешения в этих двух сравниваемых запусках была отключена.

Проверки: 54 модульных теста; 441 комбинация трассы, машины и персонажа; 108 сравнений силуэтов кузова и водителя, включая крайние настройки редактора; отсутствие считывания пикселей при холодных кэшах; ограничения памяти; редактор мышью и касанием; мобильная компоновка; сетевое меню. Команда новой проверки: npm run test:performance.

Исходная версия: cff1c77.

## Исправление загрузки — 16 октября 2026

При проверке опубликованного сайта файл 222 408 байт передал только 97 979 байт за 20 секунд. Это измерение конкретного соединения, а не доказательство общей скорости сервера. Старый загрузчик ожидал все изображения и обрывал ожидание каждого через 45 секунд.

22 используемых PNG дополнены версиями WebP: объём этих файлов уменьшен с 30 404 837 до 5 827 690 байт. Размеры изображений и их альфаканалы сохранены; RGB кодируется WebP с качеством 92. Исходные PNG оставлены в проекте.

Загрузчик показывает имена неудавшихся файлов, сохраняет уже загруженные изображения и при повторе обходит старую кэшированную копию. Ожидание увеличено до трёх минут для медленных соединений. Установка офлайн-кэша начинается после загрузки игры. Сервер отдаёт Content-Length и ETag, поддерживает HEAD и ответы 304, чтобы повторно не передавать неизменившиеся файлы.

Дополнительная проверка npm run test:loading-network намеренно возвращает ошибку для панорамы, затем проверяет успешный повтор, отсутствие повторного скачивания здоровых текстур и HTTP-кэширование. Плохую пропускную способность соединения эти изменения сами по себе не устраняют.

Первоначальные 17 JavaScript-файлов и две таблицы стилей объединены в один скрипт и одну таблицу. Сервер сжимает текст gzip и кэширует результат с ограничением количества файлов; при изменении исходника ключ кэша меняется. Офлайн-кэш использует собранные файлы. Команда сборки: npm run build, в Docker она выполняется автоматически.
